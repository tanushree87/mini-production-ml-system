\## Project Overview



This project builds a complete, cohesive production ML system around the

credit card fraud detection problem. Unlike a standard notebook exercise,

the focus is on \*\*engineering the full lifecycle\*\*:



| Phase | What is built |

|-------|--------------|

| 1 — Data \& Splitting | Temporal train/val/test split with no look-ahead leakage |

| 2 — Model Engineering | Baseline + LightGBM with imbalance handling and threshold tuning |

| 3 — Serving | FastAPI REST API with Pydantic schema validation |

| 4 — Operations | Empirical latency profiling + drift monitoring blueprint |



\*\*Dataset:\*\*

\[Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud)

(ULB, Kaggle) — 284,807 transactions, 0.17% fraud rate.  

Features V1–V28 are PCA-transformed. `Time` and `Amount` are raw.

```bash

cd mini-production-ml-system

```



\### 2. Install dependencies

```bash

pip install -r requirements.txt

```



\### 3. Add the dataset

Download `creditcard.csv` from

\[Kaggle](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud)

and place it in the `data/` directory:

```

data/

└── creditcard.csv

```



\### 4. Train the model

```bash

```

Trains the baseline and LightGBM model, tunes the classification threshold

on the validation set, and saves artifacts to `artifacts/`.


Prints the full classification report and saves `pr\_curve.png` and

`confusion\_matrix.png` to `artifacts/`.

\## Design Decisions



\*\*Temporal split over random shuffle\*\*  

Sorting by `Time` before splitting preserves the natural chronological order of

transactions. A random shuffle would leak future information into training,

producing unrealistically optimistic evaluation metrics.



\*\*PR-AUC over accuracy\*\*  

With 0.17% fraud prevalence, a model predicting all-Legit achieves 99.83%

accuracy while catching zero fraud. PR-AUC measures precision-recall trade-offs

specifically for the minority class and is insensitive to the dominant negative class.



\*\*`scale\_pos\_weight = sqrt(neg/pos) ≈ 22.76`\*\*  

The raw class ratio (518) pushed LightGBM fraud probabilities unrealistically

close to 1.0, compressing the PR curve. The square-root-scaled weight provides

balanced imbalance correction without degenerate probability outputs.



\*\*F-beta (β=2) threshold tuning\*\*  

Threshold is selected on the validation set by maximising F2-score, which

weights recall twice as heavily as precision. In fraud detection, missing a

fraud (false negative) carries higher business cost than a false alert

(false positive).



\*\*Scaler fitted on training partition only\*\*  

The `StandardScaler` is fitted exclusively on training data and serialised.

Val, test, and all inference inputs are only transformed — never fitted on —

preventing any form of data leakage.

\## API Reference



\### `GET /health`

Liveness check. Returns service status and active decision threshold.



```json

{

&#x20; "status": "ok",

&#x20; "model": "lgbm-v1",

&#x20; "threshold": 1.0

}

```



\### `POST /predict`

Score one transaction. All 30 fields are required.



\*\*Request body:\*\* `TransactionInput`

\- `Time` — float, seconds elapsed since first transaction

\- `Amount` — float, transaction amount in USD

\- `V1`–`V28` — float, PCA-transformed features



\*\*Response:\*\* `PredictionOutput`



| Field               | Type   | Description                        |

|---------------------|--------|------------------------------------|

| `fraud\_probability` | float  | Model's estimated fraud probability|

| `prediction`        | string | `"FRAUD"` or `"LEGIT"`            |

| `threshold\_used`    | float  | Decision threshold applied         |

| `model\_version`     | string | Model identifier                   |



\*\*Error responses:\*\*

\- `422` — missing field, wrong type, or null value (Pydantic validation)

\- `503` — model not loaded

\- `500` — internal scoring error

\## Drift Monitoring Blueprint



| Signal | Metric | Threshold | Action |

|--------|--------|-----------|--------|

| Feature drift | PSI per feature (weekly) | > 0.20 on 3+ features | Trigger retraining |

| Output drift | KS test on fraud probabilities | p < 0.05 | Manual review |

| Business metric | Fraud detection rate (weekly) | Drop > 10% week-over-week | Alert + investigate |

| System health | p95 latency | > 100 ms | Scale or investigate |

| System health | Error rate (4xx/5xx) | > 1% | Alert |



\*\*Retraining trigger:\*\* Any drift signal above threshold, or scheduled

monthly retraining regardless of drift.



\*\*Fallback:\*\* If model scoring fails, the service returns HTTP 500. In

production this would route to a heuristic rule (e.g. flag transactions

> $5,000 from first-time merchants) while the primary model recovers.
